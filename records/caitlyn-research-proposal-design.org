* 数据集必须满足的条件（从评测教训归纳）

1. 真实 agentic 任务 + 工具环境（Fake MCP），否则 agent 不调工具；
2. 攻击可执行（具体 IBAN/邮箱/URL），否则 ASR 必然为 0；
3. 自然、多 pattern（非 "IMPORTANT!!!" 式），否则强模型全拒；
4. 投递保证（强制首调 + 参数提示），否则等于没测；
5. benign 对照组测 FPR；
6. action 级 ground truth（MCP 审计日志）；
7. 规模足够（每 agent×defense 组合有统计力），并保留外部可比性。

* 实验部分设计讨论（2026-08-08）

** 已确认决策

1. 实验分三块：主表（现有攻击数据集，展示 ASR 下降/延迟/成本/FPR）+
   emerging 表（human-expert 新注入数据集，零样本泛化 + 首次遭遇适应）+
   case study（单案例完整生命周期：首遇漏检 → System II 进化 → 变体被拦截）。
2. 新注入数据集作为独立 contribution：围绕现有公开 benchmark 覆盖不足的
   真实新兴向量设计 5-8 个 pattern，每类 15-25 条，总 100-150 条；
   攻击可执行且经 MCP 送达；每类留 k 条 seed 给进化，其余 held-out。
3. 新颖性需要可辩护定义（模板级 holdout + 文本距离等）与泄漏控制
   （held-out 不进生成器/相似簇/redteam 上下文）。
4. Case study 选材要求初始防御真实失败、进化在有限轮数内成功、
   新抗体不引入 FPR；用真实 trace 重放，不编造。

** 下一轮待决（按依赖序）

1. 主表 agent × model 矩阵（工具通道 vs prompt 通道；是否修 openclaw/hermes MCP）。
2. natural-N 规模与 benign 池构成。
3. 指标与统计协议（action ASR、投递率、效用、延迟/token、CI、多 seed）。
4. 数据集构建流程（pattern 清单、专家设计过程、新颖性筛查、验证）。
5. case study 选材与 lifecycle trace 工具。
