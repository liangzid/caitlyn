* 项目概述

CAITLYN (Continuous Agents for Injection Threats via Lifelong Yielding Nexus) 是一个面向 LLM Agent
的、类生物免疫系统的自适应防御中间件。

核心定位：AI Agent 的"电脑管家" —— 保护计算机上所有运行中的 agent 免于注入
(injection)、投毒(poisoning)、越狱(jailbreak)等攻击，并具备通过成本感知触发
自主进化（vaccination）的能力。

系统分三层：
1. *引擎层* (caitlynd, Rust) —— 防御引擎：扫描、进化、抗体管理
2. *交互层* (caitlyn-agent, TypeScript) —— 基于 pi-agent-core 的安全管家 TUI
3. *防护层* (caitlyn-guard, Rust) —— MCP Proxy / FS Watcher / Agent Hooks / Sandbox

** 实现细节

*** core/models.rs (~250 lines)
- Antibody: 防御技能数据模型，包含 prompt/tier/threshold/stats/status
- Antigen: 逃逸攻击样本
- MemoryEntry: 快路径签名（exact/regex/semantic）
- ScanResult: 扫描结果（verdict + confidence + antibody_results）
- 枚举：DefenseTier (Specialized/General), AttackCategory, AntibodyStatus, Verdict

*** core/pool.rs (~240 lines)
- AntibodyPool: RwLock<HashMap<String, Antibody>>
- 操作：add, remove, get, get_active, list, suppress, retire, activate, update_stats
- 过滤：按 status + tier

*** core/memory.rs (~220 lines)
- MemoryBank: RwLock<HashMap<String, MemoryEntry>> + regex cache
- MemoryMatch: Exact(MemoryEntry) | NoMatch
- check(content): 遍历 exact/regex 签名，命中即返回

*** surveillance/scanner.rs (~350 lines)
- SurveillanceScanner: 多层级扫描执行器
  1. Tier 0: MemoryBank.check() —— μs 级
  2. Tier 1: 专用抗体并行（低 temperature 0.3）
  3. Tier 2: 通用抗体并行（中 temperature 0.5）
  4. Aggregation: weighted vote (malicious ×2)
  5. Cost Recording: pattern hash → CostMonitor
- run_antibody_batch: tokio join_all 并行执行

*** surveillance/cost_monitor.rs (~280 lines)
- CostRecord: pattern_hash, call_count, total_latency/tokens, success/failure rate
- should_vaccinate: 检查 latency/token 阈值 + 最小样本数 + 成功率
- compute_pattern_hash: 归一化 → SHA256

*** evolution/shm.rs (~340 lines)
- ShmEngine: adaptive temperature (0.3–0.95)
- mutate(): LLM 生成 N 个语义变体
- 8 种 mutation 操作（定义在 system prompt 中）
- parse_variants: 从 LLM JSON 输出解析为 Antibody 结构

*** evolution/affinity.rs (~340 lines)
- AffinityMaturation: 验证集评分
- evaluate(must_detect, should_detect, must_not_detect)
- 评分公式：recall × 0.7 + precision × 0.3 - FP_rate × 0.2
- must_detect 硬约束：原始攻击未检出 → 直接淘汰

*** evolution/trigger.rs (~260 lines)
- VaccinationPipeline: 编排 SHM → Affinity → Clonal Selection
- vaccinate(pattern_hash): 完整接种流程
- ValidationSet: 从 JSONL 加载 must_detect/should_detect/must_not_detect

*** llm/deepseek.rs (~160 lines)
- DeepSeekProvider: reqwest HTTP client
- generate(system, user, temp): 调用 DeepSeek API, 提取 JSON

*** storage/db.rs (~250 lines)
- init_db: SQLite pool + migrations
- 5 张表：antibodies, memory_entries, cost_records, scan_logs, valset_samples
- FTS5: memory_signatures_fts

*** storage/antibody_store.rs (~180 lines)
- load_antibodies: 从 YAML 目录递归加载
- save_antibody: 序列化到 YAML
- AntibodyFile: YAML ↔ Antibody 转换

*** storage/valset.rs (~140 lines)
- ValidationDataset: 从 valsets/ 目录加载
- 来源：AgentDojo (NeurIPS 2024) + InjecAgent (arXiv 2024)
- 攻击模板：direct, ignore_previous, system_message, injecagent, important_instructions

*** server/http.rs (~210 lines)
- axum router: /v1/scan, /v1/antibodies, /v1/cost/stats, /v1/status, /v1/health
- Json 请求/响应

*** server/mcp.rs (~500 lines)
- JSON-RPC 2.0 over stdio
- 3 tools: caitlyn_scan, caitlyn_status, caitlyn_vaccinate
- 5 个 MCP 测试

*** lib.rs (~140 lines)
- Caitlyn struct: 组合所有组件
- Caitlyn::new(): 初始化 pool, memory, cost_monitor, scanner, db
- Caitlyn::scan(): 委托给 SurveillanceScanner
- Caitlyn::vaccinate(), Caitlyn::prune(), Caitlyn::status()

*** main.rs (~80 lines)
- caitlynd CLI: --config, --port, --mcp
- 入口：HTTP server 或 MCP stdio

// 测试基础设施建议：Mock LLM Provider
struct MockLlmProvider {
    responses: Vec<String>,
    call_count: std::sync::atomic::AtomicUsize,
}

impl LlmProvider for MockLlmProvider {
    async fn generate(&self, system: &str, user: &str, temp: f64) -> CaitlynResult<String> {
        let idx = self.call_count.fetch_add(1, Ordering::SeqCst);
        Ok(self.responses.get(idx).cloned().unwrap_or_default())
    }
}

** Phase 3: 系统测试（效果评估）

目标：使用真实 LLM + 验证集评估 CAITLYN 的防御效果。

研究问题 (RQs)：
1. *检测率*：CAITLYN 对已知攻击模板的检出率 vs baselines
2. *泛化能力*：CAITLYN 对未见过的攻击变体的检出率
3. *成本降低*：接种前后 latency/token 对比（within-subject design）
4. *误报率*：对 benign 样本的误报率

Baselines：
- Regex-Guard：纯正则匹配
- LLM-Judge：单次 LLM 调用判定
- LLM-Judge+Fewshot：带 few-shot examples
- CAITLYN w/o Evolution：关闭进化，仅使用 builtin antibodies
- CAITLYN Full：完整系统

评估指标：
- TP / FP / TN / FN
- Precision / Recall / F1
- 平均延迟 (ms)
- 平均 token 消耗
- Vaccination 成功率（触发 → 生成有效抗体）

* 关键设计决策记录

1. *语言*：Rust（引擎层）+ TypeScript（交互层）—— Rust 做低延迟核心，TS 做灵活 UI
2. *进化触发*：成本驱动（cost-based），非外部标签 —— 更真实、自治
3. *部署*：Daemon + MCP 双接口
4. *分层防御*：Tier 0 (memory) → Tier 1 (specialized) → Tier 2 (general) → Tier 3 (deep, 未来)
5. *Adaptive temperature*：SHM 温度根据接种成功率自适应
6. *交互层*：基于 pi-agent-core 而非 fork pi coding-agent —— 保持独立性和可维护性
