#+TITLE: Merged Tier-1 Detection Rerun
#+DATE: 2026-08-19

* 结论记录（团长 + Agent）

- 现状：Tier 1 detector 只有 2 个（ab-classifier-injection,
  ab-instruction-hierarchy）；8 个 tier>0 non-detector 目前不参与运行时。
- 决策：实现 merged 单调用 Tier 1（META system prompt + skill 知识块 +
  待检内容），默认把 10 个 tier>0 skill 全部作为参考知识；detectors 模式
  只含 2 个 detector。merged 模式绕过 escalation gate。
- 基线 tag：paper-detection-baseline-2026-08-19（caitlyn）与
  paper-draft-baseline-2026-08-19（paper_caitlyn）已创建并推送。
- 实现：scanner.ts 新增 selectMergedSkills / buildMergedTier1Prompt /
  runMergedTier1；hybrid-scanner 与 daemon /v1/scan 支持 mode=merged、
  merged-detectors；AgentEval 两个脚本的 --caitlyn-mode 同步扩展。
- 验证：410 tests pass；daemon 冒烟一次调用 10 skills ≈ 4k tokens。
- 实验：detection-only 全量（1083 样本）先跑 merged-detectors，再跑
  merged；与基线 detection_caitlyn_20260813 对比。

* Detection-only 结果（TPR / FPR / avg latency ms / avg tokens）

| 数据集 | ensemble 基线 | merged-detectors | merged-knowledge |
|--------+---------------+------------------+------------------|
| AgentDojo | 99.6 / 6.0 / 24865 / 552 | 98.0 / 2.8 / 30104 / 1121 | 98.0 / 2.0 / 21445 / 4080 |
| ASPI | 68.8 / 6.0 / 22889 / 476 | 63.4 / 2.8 / 26416 / 1050 | 64.5 / 2.0 / 19917 / 4013 |
| SafeClawBench | 62.5 / 6.0 / 25478 / 484 | 54.1 / 2.8 / 22395 / 1010 | 52.9 / 2.0 / 20305 / 3832 |
| AgentDefense | 76.4 / 6.0 / 20663 / 498 | 73.2 / 2.8 / 22096 / 936 | 70.8 / 2.0 / 21230 / 3576 |

观察：
- merged 两个变体 TPR 均低于 ensemble 基线，SafeClawBench 降幅最大。
- FPR 明显下降（6.0 -> 2.8 -> 2.0），即误报减少约一半以上。
- 加入 10 个 non-detector 知识（merged-knowledge）没有提升 TPR，只把
  FPR 从 2.8 压到 2.0，但 token 成本约为 merged-detectors 的 3.6 倍。
- 结论：合并单调用是可行的成本/误报优化方向，但不能声称提升召回。
- 提交：d7e5f34（已推送 master）。

* 置信度校准（AUROC，用同一 shared benign 池）

| 数据集 | ensemble | merged-detectors | merged-knowledge |
|--------+----------+------------------+------------------|
| AgentDojo | 0.9796 | 0.4796 | 0.3487 |
| ASPI | 0.8152 | 0.4447 | 0.2964 |
| SafeClawBench | 0.7779 | 0.4129 | 0.2546 |
| AgentDefense | 0.8503 | 0.4425 | 0.3139 |

观察：merged 的 confidence 与 ensemble 不同，无法作为排序分数使用。
默认判定靠 verdict 标签仍可工作（低 FPR），但论文现有 ROC/PR 曲线依赖
confidence 排序；若最终采用 merged，需要额外做置信度校准或换评分机制。

* 为什么 skill 数相同但差距大（voting vs single judge）

ensemble 中两个 detector 是独立投票：
- ab-classifier-injection 单独命中 470 个 attack；
- ab-instruction-hierarchy 单独命中 5 个；
- 两者同时命中 79 个；Tier-1 union = 554。
- merged-detectors 单次调用只命中 513 个，无法复现 union。

所以差距不是"skill 数量"造成的，而是"两个独立专家投票 + 任一命中即
拦截"变成了"一个模型读完两份笔记后给一个总判定"。后者更保守
（benign fired 17 -> 7），但召回和置信度排序都变差。

* merged-pair（两个 merge 做 OR 集成，全量实测 2026-08-19）

实现：detectors merge 与 knowledge merge 并行调用，任一 malicious/
suspicious 即拦截。结果（TPR / FPR / avg latency ms / avg tokens）：

| 数据集 | ensemble 基线 | merged-pair 实测 |
|--------+---------------+------------------|
| AgentDojo | 99.6 / 6.0 / 24865 / 552 | 99.6 / 3.6 / 48393 / 5201 |
| ASPI | 68.8 / 6.0 / 22889 / 476 | 66.7 / 3.6 / 52294 / 5019 |
| SafeClawBench | 62.5 / 6.0 / 25478 / 484 | 62.1 / 3.6 / 42783 / 4843 |
| AgentDefense | 76.4 / 6.0 / 20663 / 498 | 77.6 / 3.6 / 40270 / 4512 |

观察：
- 召回基本持平（AgentDefense +1.2pp，ASPI -2.1pp，SafeClaw -0.4pp，
  AgentDojo 持平），FPR 从 6.0% 降到 3.6%。
- 代价：token 约 9-10 倍，latency 约 2 倍（40-52s）。
- 离线 OR 模拟（用前两次单独运行的记录）曾给出 100.0/74.2/66.2/77.6，
  实测更低，说明小数据集上 run-to-run 方差约 5-8pp，不能只看离线模拟。
- merged-pair 的 AUROC 仍差（0.13-0.24），confidence 排序问题没有解决。

* Latency 诊断（为什么实验中 40-50s，但直接测只有 1.5-3s）

- 单次 merged knowledge 调用（3.4k prompt tokens）直接测：2.7s，其中
  completion 60 tokens（含 52 个 reasoning tokens），可见输出不是瓶颈。
- 8 路并发同一调用直接测：avg 3.4s（max 4.2s），并发排队也不是主因。
- daemon 8 路并发 merged-pair 直接测：avg 2.5s，daemon 本身不慢。
- 全量实验期间同批短内容（avg 332 chars）却测到 baseline 20-25s、
  merged-pair 40-50s，说明当时 OpenRouter/provider 负载高，且 daemon
  stats 进化每 60s 触发额外 LLM 调用（ab-014/ab-015/...）加剧排队。
- 结论：latency 高是外部 provider 时段性延迟 + 实验期间 daemon 进化
  干扰，不是"只生成状态码"设计的问题。复测应在关闭 stats evolution
  的干净 daemon 下进行。
