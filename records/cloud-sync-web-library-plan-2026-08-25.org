* Goal

Implement paper Cloud Synchronization for attack + evolved defense library:
opt-in contribute, human audit, never auto-activate remote submissions;
library refresh via product update (no separate sync pull).

* Decisions (locked)

1. Substrate :: GitHub curated repo now (Option A); custom sync API later (B).
2. Pull :: No =caitlyn sync pull=. Fold into =caitlyn update=.
3. Release binding :: v1 library ships inside Caitlyn release (Option 1);
   layout must allow later =library-vX= channel (Option 3) under same update UX.
4. Opt-in gate :: Contribute upload only. Normal update/library-in-release is not “cloud sync”.
5. Contribute UX :: Interactive picker over *all* local entries (Option C).
6. Hub :: Same repo (=caitlyn=).
7. Pre-audit path :: =library/incoming/<contrib-id>/...=; promote into
   =antibodies/= / =antigens/= only after maintainer audit.
8. Sanitize :: Strip stats/PII/paths; antigen payloads hashed/redacted by default;
   full payload only per-entry explicit opt-in in picker.
9. Local verify :: Hard gate L2+schema for defenses; soft warn for antigens.
10. Install :: npm package =caitlyn= + wget/curl install shell.
11. Upgrade apply :: npm (and install-method aware later as needed).
12. Upgrade prompt :: TUI soft nudge + one-key confirm (not silent auto-update).
13. Library roots :: Dual roots — package shipped tree + =~/.caitlyn/library/=;
    scanner unions; local overrides by =id=.
14. Version discovery :: GitHub Releases tag as source of truth; npm applies for
    npm installs (Option C).
15. Version check policy :: Default on, delayed/idle after TUI interactive;
    =CAITLYN_OFFLINE= / config kill switch. Not the same switch as contribute.
16. Contribute auth :: First-run wizard (opt-in + =gh= auth); if no =gh=,
    still write PR-ready bundle under =~/.caitlyn/contribute/=.
