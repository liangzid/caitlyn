* 拟定的分节大纲

** Methodology 引言段
- 总起: skill 库 + System I/II + 三层映射。
- 留框架图占位注释 (团长手绘)。

** Defense and Attack Skill Specification (对应部分 1)
- skill = 自包含文件夹: config.yaml + README + 可执行体。
- defense skill 字段取自仓库: id/name/parent_id/category/tier/
  threshold/description/prompt/role/signatures/stats/deps/generation,
  可执行契约 = detect 导出 + 单行 JSON verdict。
- attack entry 字段: id/name/category/injection_point/target_agent/
  attack_template/escapes + payload.txt + README。
- escapes = 反例对防御的硬链接, 驱动定向合成。
- 为什么用文件夹而非数据库: 可人工审计/自包含/谱系。
- 图: skill spec 的 LaTeX listing (defense 左 / attack 右)。

** Three-Tier Runtime Architecture (对应部分 3, 含强耦合的工程点)
- Tier 0 microsecond gatekeeper: 常驻 worker + 进程内签名引擎,
  沙箱契约, 超时/崩溃 fail-open。
- Tier 1 single-token evaluator: escalation gate (代码化, 非 LLM 调用),
  fast/full 子集, 超时 + 并行上限, 单行 verdict。
- Tier 2 System II synthesizer + behavioral monitor:
  re-execution verifier / self-examination 等 post-hoc 检查,
  宿主为后台合成回路 (交叉引用 CEGIS 小节)。
- Algorithm 1: 带 escalation 的 System I 扫描管线。
- 耦合处理说明: tier 定义为部署角色, 机制按 tier 就地展开,
  跨 tier 的横切机制集中在工程小节。

** Counterexample-Guided Skill Synthesis (对应部分 2, 严格跟 intro)
- missed payload = counterexample = 正规范; 良性池 = 负约束。
- Algorithm 2: generate -> verify -> review -> lessons 回路。
- 生成器只读结构化画像/特征 + DAG 元数据, 原始触发文本不进入
  生成器 prompt (L1 数据边界)。
- 确定性验证器: must-detect 全部触发样本 + FP 不超过上限 +
  ReDoS 静态拒收/子进程超时。
- 独立评审 accept/revise/reject, revise 进入下一轮定向微调
  (SHM fallback 作为多样性机制, 不再称 GA)。
- 谱系: parentIds 构成的 DAG, generation/status 可追溯。
- shadow 上线 + 退役经济性。
- 图: 技能谱系 DAG (替代旧 evolution tree 图)。

** Runtime Middleware and Cost Engineering (对应部分 4)
- 部署面: localhost daemon, before/after hooks + adapter,
  FS watcher + quarantine, verdict policy, fail-open。
- 延迟/成本控制: worker pool 冷热启动, escalation, 超时/并行上限,
  token 预算, cooldown/daily limit, 截断保前缀后缀。
- 表: 工程机制 -> 目的 (替代旧 Tool Set 表)。
