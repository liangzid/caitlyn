* 论文主张与实验的对应

论文 = 防御系统（CAITLYN）+ human-expert 新兴注入数据集（benchmark）两个
贡献。实验部分回答四条主线：有效、适应、机制、稳健/长期。

* 实验结构（8 点，四组）

** 组 1：核心证据链

1. 主表 —— 现有 benchmark 下的防御效果
   - 数据集：AgentDojo（公开可比）+ natural20（自建可执行）双轨
   - 矩阵：agents × defenses × attacks；defenses =
     none/regex/llm_judge/fewshot/CAITLYN
   - 指标：action ASR（权威口径）、FPR、benign 任务成功率（效用）、
     p50/p95 延迟、token/$ 成本
   - 现状：仅 opencode × 4 防御 × n=20 pilot（无防御 55% → CAITLYN 25%）

2. 新数据集 —— human-expert 设计的 emerging 注入数据集
   - 定位：现有公开 benchmark 覆盖不足的真实新兴向量（候选：结构化工具
     输出劫持、链式跨通道、MCP schema 投毒、skill 文件投毒、agent 间传播、
     编码/多语言规避）
   - 规模草案：5-8 pattern，每类 15-25 条，总 100-150；benign 池 30-50
   - 硬约束：可执行（具体目标）、自然语言、经 MCP 送达；无防御 ASR ≥ 50%
   - 内嵌可信度验证：新颖性筛查（对照 AgentDojo/InjecAgent/natural20）、
     投递率、人工复核记录

3. Emerging 效果测试
   - E2a 零样本：静态 CAITLYN vs 静态基线，不进化
   - E2b 适应：每类 k 条 seed 进 System II，held-out 上 before → after；
     对照 CAITLYN-static vs CAITLYN+evolution
   - 记录：ASR 下降、FPR 稳定、进化成本（轮数/token/时间）、跨 pattern 迁移

** 组 2：机制层

4. Ablation：Tier0-only / Tier1-only / fewshot / consistency recheck /
   similar clusters / SHM / shadow
5. Case study：单案例完整生命周期（首遇漏检 → Tier1 → System II 进化 →
   变体被拦截），真实 trace，不编造
6. 成本分析：延迟/token/$ 构成与 Pareto（ASR vs 成本）

** 组 3：对抗稳健性

7. Adaptive attack + poisoning
   - 需先定义攻击者能力模型（白盒/黑盒、能否见判定输出）
   - poisoning：恶意抗原流下 benign FPR 增量
   - adaptive：规避变体（编码/改写）下的 ASR

** 组 4：长期性

8. 长期演化：多 pattern 按时间序列到达 → 覆盖增长/遗忘/归档；
   Tier-0 仿真即可

* 已确认的设计红线

1. action 级 ground truth（MCP 审计），不以输出文本猜测
2. 投递保证（强制首调 + 参数提示）

4. ≥3 seed 重复、CI、统计口径
5. 不 mock；case study 用真实 trace

AgentDefense-Bench 的 Tier-0（便宜）与 none-vs-caitlyn 两列（可选）。

** Detection-only sweep（feedback 第一优先级）

- 数据源：AgentDojo-S250、ASPI-S、SafeClawBench-S240、AgentDefense-S1908、
  natural20，共五个。
- 防御：regex / llm_judge / llm_judge_fewshot / pi_detector / CAITLYN。
  spotlighting 与 tool_filter 不是内容分类器，不进 detection sweep。
- 统一 benign 池：AgentDefense-Bench 250 条 benign + 默认工具输出，
  避免跨数据集 FPR 不可比（AgentDojo benign 是用户 prompt，不能当
  工具输出 benign 用）。
- 指标：TPR、FPR、TPR@fixed FPR、p50/p95 latency、token/$ 成本。
  AUROC/AUPRC 只对输出连续分数的防御报（regex 匹配数、CAITLYN
  confidence；llm_judge 无分数则不报）。
- 现有 run_detection_sweep.py 只覆盖 ADB × CAITLYN，需扩展为全矩阵。

** Delivery-aware e2e 口径

主表每格报：delivery rate、defense block rate、action ASR（按送达）、
benign task success、latency/token。MCP-native 与 prompt-delivery 两类
agent 分开报，delivery failure 不与 defense success 混淆。
缺口：benign task success（任务完成质量）评分器尚未实现。

** System II before/after（= E2b 细化）

- seed k ∈ {1, 3, 5}；CAITLYN-static vs CAITLYN+evolution；
  held-out 不进 generator/similar-cluster/redteam 上下文。
- 指标：held-out detection rate / action ASR、benign FPR、
  evolution rounds、token、wall-clock、accepted/rejected candidate 数。
- 可选：pattern A 训练、pattern B 测试的 cross-pattern transfer。

** Hard benign 降级

不自建 HardBenign-50 benchmark。如需回应 keyword blocker 质疑，从公开
benign 自动筛含 injection-like 表层词（curl/bash/execute/ignore/
IMPORTANT/email/forward 等）的 slice，单独报 FPR，放 appendix。
