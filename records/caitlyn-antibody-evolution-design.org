#+TITLE: CAITLYN 抗体进化（免疫 System 2）设计讨论
#+AUTHOR: Zi Liang (团长) + Agent
#+DATE: 2026-08-01

* 背景

Stage 1 重新设计疫苗/进化链路。团长明确：现有 evolution 相关代码视为垃圾，
按讨论全新设计，不受现有代码影响。测试相关工作仍悬置。

* 已确认的设计决策

1. 叙事：免疫系统故事，不叫 GA。System 1 = 快防御（Tier0+Tier1 实时扫描）；
   System 2 = 慢免疫（抗原-抗体库 DAG 演化）。变异只是免疫框架内的优化操作。
2. 触发层级：
   - 主触发 = 从 OS 与 agent 读取统计量，偏离正常基线（EWMA + p99）触发免疫应答；
     即使没有捕获注入文本，也要生成"察觉未知"的记录/产物。
   - 显式触发 = 用户/CLI/TUI/agent 主动调用。
   - 成本/频率触发降为辅助（仅效率优化，不作主故事）。
   - 事件驱动（Tier0 命中但 Tier1 放行）已砍掉。
3. StatsCollector：独立组件，作为 daemon 的一部分。事件产生端无状态追加
   ~/.caitlyn/stats/events.jsonl；daemon 聚合、基线建模、异常判定；
   baseline.json 定期持久化。信号源四层清单已确认（Agent 行为、文件系统、
   OS/网络、免疫系统自身信号）。
4. 自治等级配置（[evolution]）：
   - autonomy = "auto"（有样本路径，默认；经确定性验证约束 + 评审）
   - unknown_threat_action = "candidate"（无样本路径，默认；泛化候选需确认）
   - record / candidate / auto 三档；candidate 自动升级机制留第二版。
5. 抗原构成：主抗原 = 触发样本；相似样本簇作为参考上下文防过拟合（不进入硬约束）。
6. 父代选择：无单独选亲本；LLM 读取整个抗体 DAG（结构化元数据）后直接综合合成。
   meta vs full context 为实验点，配置项 dag_context = "meta" | "full"。
7. 生成结构：全 DAG 合成为主生成器（一次产出 N 个候选）；SHM 仅作候选全部失败时
   的定向微调兜底。
8. 评估：放弃大规模验证集统计评估（无足够攻击样本）。改为轻量确定性约束
   （抗原簇必须全中；少量良性样本如 5 个中 <=1 FP）+ LLM 独立评审。
9. Loop 结构（LLM loop engineering 思路）：
   state = {目标, 抗原画像, DAG 谱系, 候选历史, 失败教训}；
   生成器 LLM -> 确定性验证（真实工具，抗原簇+良性样本）-> 独立评审 LLM ->
   更新 state。accept 固化（受自治等级约束）；revise 建议进下一轮；
   reject / 无进展 / 预算耗尽则升级降级。需显式终止条件、最大轮数/预算、
   上下文管理（防 context rot）。
10. 评审者身份（已确认）：独立评审模型。生成器与评审者分离
    （生成 deepseek-v4-pro、评审 deepseek-v4-flash）。输入 = 候选 + 确定性验证
    结果 + 库背景；输出结构化评审单（accept/revise/reject + 具体建议）。
    理由：loop engineering 证据表明自我评审容易偏袒自己的产物。
11. 失败教训记忆（已确认，方案 1）：独立于 DAG 持久化教训库
    ~/.caitlyn/evolution/lessons.jsonl；每条 = {关联抗原簇/类别, 轮次, 候选摘要,
    确定性验证结果, 评审结论与建议, 与上轮相比的改动}；循环开始时按抗原簇筛选
    最近 K 条（10）+ LLM 聚合的"教训摘要"注入生成器；评审者不喂教训，保持独立；
    教训不进入 DAG 谱系元数据，避免 DAG 膨胀。
12. 候选晋升（已确认，双通道）：仅适用于 unknown_threat_action = "candidate"
    产生的泛化候选。
    - 显式批准：用户/agent 对 candidate 明确 approve → 立即 active。
    - shadow 观察期：candidate 以影子模式注入扫描（只记录、不拦截）；观察窗口
      （7 天或累计 N 次扫描，先到为准）内 0 FP 且至少 1 次被确认的可疑命中 →
      自动晋升；出现 FP 或窗口到期未达标 → 降 dormant（保留供人工复审）。
    - record 模式永不生成候选；auto 模式无样本时不自动激活。
13. DAG 生命周期（已确认，方案 1）：active 抗体维护 evidence（命中、FP、最近使用），
    score = hits - 5*FP + 时间衰减；active 上限 256，超出自动降 score 最低者为
    dormant；score < 0 或 90 天无命中且有覆盖后代 → dormant；dormant 保留 30 天
    供复审，过期无人恢复 → 归档（进 git，不丢数据）。
14. 重复度控制（已确认，方案 2）：仅靠 LLM prompt 约束（生成器注入现有签名清单，
    要求不重叠）+ 评审单必填"与现有库重复性"字段；v1 不做确定性 Jaccard 与
    embedding 相似度。
15. 对抗投毒防护（已确认，L1-L6 全进 v1）：
    - L1 数据边界：外部文本不整段进生成器，daemon 提炼为结构化抗原特征；
      外部字段带数据标记与长度上限，prompt 声明"抗原是数据而非指令"。
    - L2 验证沙箱：确定性验证是唯一信任锚；正则签名验证带超时与危险模式
      拒绝（防 ReDoS）。
    - L3 评审强化：评审输出强制 JSON schema（accept/revise/reject + 理由 +
      重复性）；候选代码以代码块包裹视为数据；低温度。
    - L4 教训库完整性：append-only；仅由"验证结果 + 评审输出"生成；
      schema 校验；原始外部文本禁止写入。
    - L5 资源护栏：抗原簇冷却期、每日演化次数上限、每轮预算与最大轮数。
    - L6 退役保护：score 竞争只在高分区进行；带"被后代覆盖"关系才允许因排名
      退役；单纯低分不挤占安全抗体。
    - 第二版：评审一致性抽查（同输入重评比对）、主动红队演练。

* 实现计划（已确认）

命名决定：全部使用 evolution。目录沿用 src/evolution/（重写，不用 immune）；
配置段 [evolution]；CLI 命令沿用 caitlyn vaccinate（原 help 中缺失的命令，
与免疫接种叙事一致）。

实现顺序（8 个 commit，每单元一个 commit 并配足够 unit tests）：

1. C1 feat(evolution): config schema + 默认值
   - EvolutionConfig：autonomy / unknown_threat_action / dag_context / generator_model /
     reviewer_model / candidates_per_run / max_rounds / max_tokens_per_run / active_cap /
     fp_penalty_weight / score_decay_days / dormant_grace_days / retire_inactive_days /
     benign_samples / max_benign_false_positives / regex_timeout_ms / shadow_window_days /
     shadow_min_scans / lessons_per_cluster / cooldown_minutes / daily_evolution_limit /
     evolution_dir。
   - 默认值：autonomy=auto, unknown_threat_action=candidate, dag_context=meta,
     generator=llm.model, reviewer=llm.small_model, candidates_per_run=3, max_rounds=5,
     max_tokens_per_run=40000, active_cap=256, fp_penalty_weight=5, score_decay_days=90,
     dormant_grace_days=30, retire_inactive_days=90, benign_samples=5,
     max_benign_false_positives=1, regex_timeout_ms=200, shadow_window_days=7,
     shadow_min_scans=50, lessons_per_cluster=10, cooldown_minutes=60,
     daily_evolution_limit=10, evolution_dir=~/.caitlyn/evolution。
   - config.toml 补 [evolution] 示例段；旧 [vaccination] 保留不动。
   - unit tests：临时 TOML 验证默认值、覆盖、非法枚举回退、路径缺省。
2. C2 feat(evolution): antibody DAG store
   - 节点/血缘（parent_id）/evidence（hits/FP/lastUsed）/score=hits-5*FP+时间衰减；
     active 上限 256 超出降 score 最低者 dormant；score<0 或 90 天无命中且有覆盖后代
     → dormant；dormant 30 天无人恢复 → archive（append-only 归档，不丢数据）；
     L6 退役保护（有后代覆盖才允许因排名退役）。
   - 持久化到 evolution_dir（nodes.json + edges 由 parent_id 推导或单独边表）。
   - unit tests：CRUD、评分、上限淘汰、退役、归档、恢复、血缘查询。
3. C3 feat(evolution): lessons store
   - lessons.jsonl append-only；schema 校验；来源白名单（verification | review）；
     原始外部文本禁止写入；按抗原簇筛选最近 K 条 + LLM 聚合摘要读取接口。
   - unit tests：写入、非法来源拒绝、schema 校验、按簇筛选、摘要输入构造。
4. C4 feat(stats): events collector + EWMA/p99 基线 + 异常触发
   - 事件产生端无状态追加 ~/.caitlyn/stats/events.jsonl；daemon 聚合（StatsCollector）；
     EWMA 基线 + p99 异常判定；baseline.json 定期持久化；冷却期与每日上限（L5）；
     信号源四层（agent_behavior / filesystem / os_network / immune_self）。
   - unit tests：事件追加、EWMA 计算、p99、异常判定、基线持久化、冷却、日限。
5. C5 feat(evolution): deterministic verification sandbox
   - 抗原簇必须全中；良性样本 FP<=1；正则签名验证带超时与危险模式拒绝（L2）。
   - unit tests：全中/漏检/FP 判定、正则超时、危险模式拒绝（ReDoS）。
6. C6 feat(evolution): LLM generate-review loop
   - state={目标, 抗原画像, DAG 谱系, 候选历史, 失败教训}；生成器 prompt
     （全 DAG meta/抗原特征/教训摘要/签名清单，L1 数据边界）；
     评审 JSON schema（accept/revise/reject + 理由 + 重复性，L3）；预算与轮数终止
     （L5）；生成后先确定性验证再评审；revise 建议进下一轮；reject/无进展/预算耗尽
     终止并写教训。
   - unit tests：loop 状态流转、预算/轮数终止、评审单解析、教训自动写入。
7. C7 feat(evolution): candidate shadow mode + 双通道晋升
   - candidate 注入扫描（只记录不拦截）；观察窗口 7 天或 N 次扫描；0 FP 且 >=1 被确认
     可疑命中 → active；FP 或窗口到期未达标 → dormant；显式 approve → active。
   - unit tests：shadow 记录、晋升判定、降级判定、approve。
8. C8 chore(evolution): 接线与清理
   - CLI caitlyn vaccinate 实现（显式触发）；daemon StatsCollector 挂入；扫描路径
     shadow 注入点；删除旧 GA 文件（affinity/shm/memory-bank/cost-monitor/pipeline/
     validation-set 旧实现）；npm run build + 全量 test 通过。

测试要求（团长明确）：每一部分都要经过足够 unit tests 保证正确性；新测试必须隔离
（临时目录注入路径），不得写真实 config.yaml / 库文件 / 项目根 jsonl。
