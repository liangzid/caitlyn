# ZERI: Zero-Trust Evolution for Reinforced Immunizer

## Research Question

**Can LLM agents autonomously immunize against emerging injection or poisoning attacks?**

## Motivation

LLM agents have become a vital application domain for large language models, but they are increasingly exploited. Real-world CVEs already target major agent frameworks:

| Framework | CVEs |
|-----------|------|
| CrewAI | CVE-2026-2275, CVE-2026-2285, CVE-2026-2286, CVE-2026-2287 |
| LangGraph | CVE-2025-67644, CVE-2025-64439 |
| Codex | CVE-2025-59532, CVE-2025-61260 |
| Hermes Agent | CVE-2026-53870, CVE-2026-9354, CVE-2026-7397 |
| OpenClaw | CVE-2026-28482, CVE-2026-26324, CVE-2026-32897 |

Attack vectors include web/local content injection, MCP tool poisoning, and skill file injection. A core observation: **injected or poisoned texts are appended and included into the agent's context without verification**, making them trivially exploitable.

## Current Defense Landscape

### Category 1: Isolated Protection Layers

External sandboxing or filtering layers that sit between the agent and its tools/environment.

- **Approach**: Rule-based filtering, sandboxing, permission gating.
- **Drawbacks**:
  - Utility degradation — over-blocking harms task completion.
  - Cannot execute query-aware defenses — static rules lack situational understanding.
  - Observed to be non-deployable in real-world dynamic environments (AgentDyn, Preprint 2026).

### Category 2: Security Auditing Agents / Plugins

| System | Venue | Approach | Limitations |
|--------|-------|----------|-------------|
| **AgentWard** | Preprint 2026 (THU) | Lifecycle security scanning with LLM-as-Judge | Not agentic; OpenClaw-only; no experimental results |
| **ClawGuard** | Preprint 2026 (SMU) | White-box ruleset generated by LLM prompting; runtime permission checks | Not agentic; only permission checks, no adaptive defense |
| **SafeMCP** | ACL 2026 | Proactive power regulation via environment-grounded look-ahead reasoning | — |

### Common Shortcomings

1. **Fixed defenses**: All existing approaches use static rule-sets — once deployed, they cannot adapt.
2. **Not agentic**: Defenses are passive filters, not reasoning entities that understand the attack and respond dynamically.
3. **Known attacks only**: Designed against catalogued attack patterns; defenseless against novel or evolved injection strategies.
4. **Manual maintenance**: Security engineers must manually audit layers and update rules — no autonomous evolution.

## Research Gap

```
Fixed Defense                          →  Flexible Defense
Rule-sets for permission/filtering     →  Agentic Defense
For known attacks only                 →  Both existing AND emerging attacks
Cannot evolve new defenses             →  Learns from defending previous attacks
Manual layer/rule auditing             →  Autonomous defense generation
```

## Proposed Approach: ZERI

**ZERI** (Zero-Trust Evolution for Reinforced Immunizer) proposes an **agentic, evolvable defense sub-agent** that:

1. **Flexible Integration**: Deploys as a defense agent/sub-agent that can be integrated into existing agent frameworks without requiring framework-specific modifications.

2. **Agentic Defense**: Reasons about incoming content and tool calls in context — not just pattern-matching, but understanding intent, anomalies, and attack semantics.

3. **Evolvable**: Learns from every defense action. Attack patterns that are successfully identified and blocked feed into an evolving defense repertoire, enabling the system to autonomously generalize defenses against novel variants.

4. **Zero-Trust Posture**: Treats all external content (web pages, tool outputs, MCP responses, skill files) as untrusted by default. Verification is continuous and context-aware rather than a one-time gate.

## Key Challenges

1. **Defense generalization**: How to abstract from a concrete attack instance to a reusable defense rule without overfitting or over-blocking.
2. **Utility-preserving immunity**: Evolved defenses must not degrade task completion rates (cf. isolated protection layers).
3. **Online adaptation safety**: Learning from attacks at runtime must not itself become an attack surface (adversarial poisoning of the defense mechanism).
4. **Evaluation methodology**: No standard benchmark exists for adaptive, evolving agent defenses — constructing realistic attack evolution scenarios is an open problem.

## Target Outcomes

1. A prototype defense sub-agent (ZERI) integrated with at least one major agent framework.
2. An evolvable defense memory mechanism that generalizes from observed attacks.
3. Empirical evaluation showing defense success rate improvement over static baselines on both known and novel attacks, without significant utility degradation.
4. A benchmark or test harness for evaluating adaptive agent defenses under attack evolution.
